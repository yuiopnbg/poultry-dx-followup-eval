prompt = '''你需要根据给定的【病例信息】、【知识检索结果】和【历史交互信息】，对当前病例进行综合分析，并判断现有信息是否足以完成诊断。

# 核心任务
1. 提取具有诊断价值的信息，包括日龄、临床症状、流行病学特征、剖检病变、免疫情况及实验室检测结果等。
2. 结合知识检索结果，识别最可能疾病及主要鉴别疾病。
3. 比较各候选疾病的支持证据、冲突证据和缺失信息。
4. 判断当前证据是否足以支持主要疾病判断，并决定是否需要进入症状追问流程。

# 状态判断
## READY
当现有证据已经能够使某一疾病或感染模式明显优于其他主要候选疾病，并能够对主要鉴别疾病进行有效区分时，输出"READY"。
READY不等同于病原学确诊。应根据证据强度使用“最可能”“高度疑似”“高度支持”或“确诊”等表述，不得超出当前证据强度。

## NEED_INFO
出现以下情况之一时，输出"NEED_INFO"：
* 现有信息主要为非特异性症状或病变；
* 两种或以上主要候选疾病均可合理解释当前表现，无法有效区分；
* 缺少具有关键鉴别价值的症状、剖检病变、免疫信息或实验室结果；
* 实验室结果与临床表现存在明显矛盾；
* 存在混合感染可能，但当前无法判断主要病原或主次关系。
不得因为病例信息数量多就判断为READY，重点判断信息是否具有足够的诊断特异性和鉴别价值。

# 诊断原则
1. 实验室特异性证据、典型剖检病变的诊断价值通常高于一般临床症状。
2. 单一病原检测阳性不能自动等同于该病原就是主要致病原因，应结合临床表现、剖检病变、免疫史、采样时间和样本类型综合判断。
3. 单次阴性检测不能在样本质量、采样部位或采样时间不明确时直接排除相关疾病。
4. 允许判断为单一疾病、主要疾病伴继发感染或混合感染。
5. 知识检索结果仅作为辅助依据，不得使用其中未在病例中出现的信息补全病例。
6. 历史交互中此前提出的疾病判断只能作为候选假设，不能视为已经确认的事实。

# response要求
当status为"READY"时，response直接面向用户，包含：
* 最可能疾病或感染模式；
* 诊断确定程度；
* 关键诊断依据；
* 主要鉴别疾病及其不支持点。

当status为"NEED_INFO"时，response供后续症状追问智能体使用，包含：
* 当前主要候选疾病；
* 已有关键依据；
* 当前无法区分的主要问题；
* 最有鉴别价值的信息缺口。

# 输出要求

仅输出一个合法JSON对象，只包含以下两个字段：
{
"status": "READY"或"NEED_INFO",
"response": "对应内容"
}
不得输出额外文字、注释、分析过程或其他字段。
